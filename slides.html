cmux Academy

A hands-on course for the terminal built for running coding agents

Press → to advance · S speaker notes · O overview · F full screen · back to the academy

Five modules, roughly three hours in total. Keep a cmux window open next to this deck and try each thing as it comes up.

What cmux is

  • A native macOS terminal, built on Ghostty
  • Vertical tabs in a sidebar, one per project or agent
  • A notification panel that tells you which agent needs you
  • An in-app browser and diff viewer
  • A CLI and socket API, so scripts can drive all of it

Your Ghostty config still applies. cmux adds the multi-agent layer on top.

Module 1

Orientation

Get the vocabulary right and everything else gets easier.

Five levels

Windowa macOS window · ⌘⇧N
Workspacea row in the left sidebar · ⌘N
Panea split region · ⌘D / ⌘⇧D
Surfacea tab inside a pane · ⌘T

A panel is what a surface shows: a terminal (Ghostty) or a browser.

Same thing, two names

  • The UI sometimes says tab; the API says workspace
  • "Tab" inside a pane means a surface
  • When you use the CLI, use workspace and surface

Refs look like workspace:2, pane:3, surface:4. Pass --id-format uuids if you want UUIDs.

Where am I?

cmux tree                       # everything, as a tree
cmux identify                   # the ids of this shell
echo $CMUX_WORKSPACE_ID $CMUX_SURFACE_ID

cmux sets these variables in every terminal it opens, so scripts know where they run.

Workspaces and groups

  • One workspace per project, or per agent task
  • ⌘N new · ⌘⇧R rename · ⌘1…9 jump
  • ⌘⇧G group selected workspaces, ⌃⌘. collapse
  • ⌃⌘S save the layout as a template
Tasks m2-4, m2-6, m2-8

The same layout from the CLI

cmux new-workspace --name scratch --cwd ~
cmux new-split right
cmux new-split down --command "ls"
cmux tree
cmux close-workspace --workspace workspace:5   # your ref will differ

Anything you can do by keyboard, a script can do. That is the whole idea of Module 5.

Task m2-7

Module 3

Working with agents

The reason cmux exists.

The problem

  • Three Claude Code sessions, three projects
  • You cannot watch all of them
  • You do not want to poll them

cmux turns "which one is waiting?" into something the terminal tells you.

Notifications

⌘IShow the notification panel
⌘⇧UJump to the latest unread
⌥⌘UToggle unread on the current item
make test; cmux notify --title "Tests" --body "finished"
cmux list-notifications
cmux clear-notifications

Your Claude Code is launched through a cmux wrapper, so its hooks are already registered. You do not need to add any.

Tasks m3-1, m3-2, m3-9

Status, progress, log

cmux set-status build "passing" --color "#2ea043"
cmux set-progress 0.6 --label "Migrating"
cmux log --level info --source deploy "step 3 of 5"

cmux clear-status build
cmux clear-progress

Use a unique key per tool so different scripts do not overwrite each other's pills.

Tasks m3-3 to m3-5

Review what the agent changed

cmux diff --unstaged        # also --staged, --branch, --last-turn
cmux markdown open PLAN.md  # live-reloading viewer
  • Diff viewer: J/K scroll, / search files, ⌃⌘⇧D to open
  • --last-turn is the one to reach for after an agent finishes
Tasks m3-6, m3-7

Agent teams

cmux claude-teams
cmux claude-teams --continue
cmux claude-teams --model sonnet

Teammate agents appear as native cmux splits instead of tmux panes, with sidebar metadata and notifications.

Module 4

The built-in browser

Docs and localhost next to your terminal.

Open one

⌘⇧LOpen a browser
⌥⌘DBrowser split to the right (⇧ for down)
⌘LAddress bar
⌥⌘IDeveloper tools
⌥⌘↩Focus mode: the page gets your keys
cmux browser open http://localhost:3000
Tasks m4-1 to m4-3

Script the browser

cmux browser snapshot --interactive      # page as text, with refs
cmux browser get title
cmux browser eval "document.title"
cmux browser wait --text "Ready" --timeout-ms 5000
cmux browser click "button.submit"
cmux browser screenshot --out ./shot.png

This is how an agent can look at the app it just built. It also works for you in shell scripts.

Tasks m4-4 to m4-6

Module 5

Automate and customise

Make cmux yours.

Drive other terminals

cmux tree                                    # find the ref
cmux send --surface surface:4 "npm test"
cmux send-key --surface surface:4 enter
cmux read-screen --surface surface:4 --lines 20

One agent can start work in another pane and read the result back. --scrollback reads history too.

Task m5-5

Two config files

Ghostty config
~/.config/ghostty/config

Fonts, themes, scrollback, terminal behaviour

cmux.json
~/.config/cmux/cmux.json

Shortcuts, sidebar, notifications, browser, custom commands

cmux config path
cmux config doctor
cmux reload-config        # both files, no restart (⌘⇧,)

Back up cmux.json before editing. It is JSON with comments.

Tasks m5-1 to m5-3

Your own shortcuts

{
  "shortcuts": {
    "bindings": {
      "showNotifications": ["ctrl+b", "i"],
      "toggleSidebar": "cmd+b",
      "splitRight": ""
    }
  }
}
  • A string is a single shortcut; a two-item array is a chord
  • An empty string or null unbinds it
Task m5-4

Custom workspace layouts

{
  "actions": {
    "review-setup": {
      "type": "workspace",
      "title": "Review Setup",
      "workspace": {
        "name": "Review", "cwd": "~/code/app",
        "setup": "git fetch --all --prune",
        "layout": {
          "direction": "horizontal", "split": 0.5,
          "children": [
            { "pane": { "surfaces": [
              { "type": "terminal", "name": "Claude",
                "command": "claude", "focus": true } ] } },
            { "pane": { "surfaces": [
              { "type": "terminal", "name": "Shell" } ] } }
          ]
        }
      }
    }
  }
}

Adapted from the cmux docs. Reload, then run it from the command palette.

Tasks m5-6, m5-8

Remote work

cmux ssh user@host --name "dev box"
cmux ssh user@host --transport mosh
cmux mosh-tmux user@host --session agent-main

A remote session lives in a workspace like any other, so notifications and layouts work the same way.
